# DEVLOG — 关键决策记录

供博客引用的开发日志。每个里程碑记录：做了什么、为什么这么做、踩了什么坑。

## M0 — 全局约定（先于一切）

- **像素中心约定**：像素 `(i, j)` 的采样点在 `(i + 0.5, j + 0.5)`（与 D3D 一致）。所有边函数、深度、纹理采样都以此为基准。
- **屏幕坐标**：帧缓冲第 0 行是屏幕**顶部**。NDC +Y 向上，投影到屏幕时 `y_s = (1 - ndc.y) * 0.5 * H` 完成翻转。
- **相机**：右手系，+Y 向上，相机看向 -Z（GL 惯例）。透视矩阵标准 gluPerspective 形式，`w_clip = -z_view`（在相机前方为正）。
- **深度**：帧缓冲内存"视空间距离" `d = -z_view`（正值，越小越近），Float32Array，初始 +Infinity，深度测试用严格小于（`d < depth`），同深度时先画者赢。
- **确定性**：一切随机来自 `mulberry32(seed)` 种子 PRNG，禁止 `Math.random`。黄金图一旦生成即冻结，测试对拍容差为 **0**。
- **参考实现纪律**：每个里程碑先在 `tools/reference/gen_mX.ts` 写一个自包含的参考实现生成黄金图（只允许复用数学库/帧缓冲/几何体等"夹具"，不允许复用被测算法），再写正式实现（src/）对拍。

## M2 — Bresenham 直线（全象限整数实现）

- **双实现对拍**：正式实现用"全象限误差累积"变体（单一循环，无八分体分支）；参考实现用教科书"八分体归约"版（swap 到第一八分体、误差项 D）。两者在**无平局**直线上被 800 条种子随机扫描证明逐像素等价。
- **平局是约定不是正确性**：当中点恰好落在理想线上（如 dx 为偶的浅线）时，不同正确实现会选不同像素。本项目冻结"全象限变体、平局走对角步进"的行为，用三个手工求得的像素序列钉死在测试里（含反向不对称性）。
- **无平局判据**：轴对齐与精确 45° 恒无平局；其余情形步进轴跨度为奇数 ⟹ 无平局（2·dy·Δx 与 dx·(2Δy+1) 奇偶性不同）。黄金场景全部选用无平局线。
- **性质测试兜底**：端点必画、绘制序 8-连通、每点到线段距离 ≤ 0.51 ——这三条不依赖任何参考实现，是算法正确性的独立证据。
- **端点定义**：直线连接两个整数格点（像素索引本身），而非像素中心；黄金图与性质测试均基于此约定。

## M3 — edge-function 三角形填充 + top-left rule

- **核心设计**：`rasterizeTriangle` 是 M3~M9 一切光栅化的唯一核心。屏幕空间逐像素直接求值三条边函数（不走向累积），换来与参考实现的逐位一致（IEEE 基本运算确定性），代价是每像素 ~10 次浮点乘加 —— 在 512² 场景下实测仍轻松 60fps，性能换确定性值得（M9 benchmark 有数据）。
- **top-left 规则推导**（y-down、正有向面积=视觉顺时针）：`E==0` 的采样点仅当边为 left（`dy<0`）或 top（`dy==0 && dx>0`）时包含。证明要点：相邻两三角形反向遍历共享边，方向 d 与 -d 中恰有一方满足该谓词 ⟹ 总和且互斥。
- **水密性验证不依赖参考实现**：600 对种子随机相邻三角形拼矩形，断言矩形内每个像素中心恰好覆盖一次、矩形外零覆盖 —— 这是不变量级的证据；1×1 到 40×40、两种对角线方向都覆盖。
- **解析覆盖计数**：直角三角形 (0,0)(8,0)(0,8) 的斜边恰穿过 i+j=7 的像素中心带，top-left 规则把这些点判给"另一侧"，故覆盖数 = #{i+j≤6} = 28，与实现输出一致。
- **环绕归一化**：area2 < 0 时交换 v1/v2（属性随之换序），调用方不需要关心顶点序；背面剔除是调用方基于同一 area2 公式的独立决策。

## M4 — z-buffer（屏幕空间线性 z 插值）

- **语义**：深度缓冲存视空间距离 d = -z_view（Float32，初始 +Infinity），测试 `d < depth`（严格小于）。黄金场景用**正交投影** —— 此时屏幕空间线性 z 是精确插值，参考/正式实现语义完全对齐，黄金图全里程碑保持回归有效。
- **踩坑**：`Framebuffer` 构造函数最初没把深度初始化为 +Infinity（只有 clear() 做），导致首版黄金图"双方都画了空图"假通过。教训：黄金对拍必须配一条**独立的内容性断言**（本里程碑补了遮挡/插值/平局三类）。
- **平局的真相**：`d < depth` 严格小于只在深度**逐位相同**时保证先画者赢。常数 z 的三角形插值结果是 (Σλᵢz)/Σλᵢ，浮点噪声可使其略小于 6.0 而被后画者覆盖 —— 这不是 bug，是 float64 插值的物理现实。二进制精确几何（2 的幂坐标 ⟹ 边函数/权重均为精确 dyadic 值）可构造逐位相同的平局，用它钉死先画者赢语义；非精确几何的同深度对只断言确定性（噪声方向冻结进黄金图）。真实 GPU 用定点深度正是为了消除这类噪声。
- **插值公式冻结**：d = (Σλᵢ·dOverWᵢ)/(Σλᵢ·invWᵢ)，一律直接除法。invW ≡ 1（仿射绘制）时退化为纯屏幕空间线性 z；M5 起透视绘制走同一条公式获得透视校正深度。

## M5 — 透视校正纹理（u/z、v/z、1/z）

- **核心公式**：屏幕空间线性插值 `(u/w, v/w, 1/w)`，逐像素 `u = (Σλᵢ·uᵢ/wᵢ)/(Σλᵢ·1/wᵢ)`。同一套机制顺手给出透视校正深度 `d = (Σλᵢ·dᵢ/wᵢ)/(Σλᵢ·1/wᵢ)` —— M4 的仿射路径（invW≡1）只是它的特例，一个核心吃下两种语义。
- **swimming 检验场**：黄金场景是掠射角地面四边形（近端 d=2、远端 d=8 的棋盘格），并配**解析对拍**：对 >2000 个深内部像素，用"像素中心光线与已知平面求交"独立算出 UV 再采样，要求与渲染输出逐位相同；同时断言屏幕空间线性 UV 在同一场景偏差 >0.02 —— 证明测试对"忘除 w"这类错误有杀伤力。
- **纹素边界歧义**：解析 UV 恰落在纹素边界 ±ULP 时，nearest 的格选择随浮点噪声翻转（如 u·64 = 48.0）。这不是插值 bug；解析对拍跳过边界 ±1e-3 的像素，黄金图不受影响（参考与正式同噪声同翻转，确定性保持）。
- **投影公式冻结**：`sx = (clip.x/w + 1)*0.5*W`、`sy = (1 - clip.y/w)*0.5*H`、一切属性 `attr/w` 直接除法 —— 参考实现逐位复刻同一串运算，IEEE 确定性保证对拍 0 容差可行。
- **采样器约定**：repeat 环绕（uu = u - floor(u)）；nearest = floor(uu·W) 钳位；bilinear = fx = uu·W - 0.5，索引环绕，先横后纵 lerp。
