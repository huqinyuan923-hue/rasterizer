# DEVLOG — 关键决策记录

供博客引用的开发日志。每个里程碑记录：做了什么、为什么这么做、踩了什么坑。

## M0 — 全局约定（先于一切）

- **像素中心约定**：像素 `(i, j)` 的采样点在 `(i + 0.5, j + 0.5)`（与 D3D 一致）。所有边函数、深度、纹理采样都以此为基准。
- **屏幕坐标**：帧缓冲第 0 行是屏幕**顶部**。NDC +Y 向上，投影到屏幕时 `y_s = (1 - ndc.y) * 0.5 * H` 完成翻转。
- **相机**：右手系，+Y 向上，相机看向 -Z（GL 惯例）。透视矩阵标准 gluPerspective 形式，`w_clip = -z_view`（在相机前方为正）。
- **深度**：帧缓冲内存"视空间距离" `d = -z_view`（正值，越小越近），Float32Array，初始 +Infinity，深度测试用严格小于（`d < depth`），同深度时先画者赢。
- **确定性**：一切随机来自 `mulberry32(seed)` 种子 PRNG，禁止 `Math.random`。黄金图一旦生成即冻结，测试对拍容差为 **0**。
- **参考实现纪律**：每个里程碑先在 `tools/reference/gen_mX.ts` 写一个自包含的参考实现生成黄金图（只允许复用数学库/帧缓冲/几何体等"夹具"，不允许复用被测算法），再写正式实现（src/）对拍。

## M2 — Bresenham 直线（全象限整数实现）

- **双实现对拍**：正式实现用"全象限误差累积"变体（单一循环，无八分体分支）；参考实现用教科书"八分体归约"版（swap 到第一八分体、误差项 D）。两者在**无平局**直线上被 800 条种子随机扫描证明逐像素等价。
- **平局是约定不是正确性**：当中点恰好落在理想线上（如 dx 为偶的浅线）时，不同正确实现会选不同像素。本项目冻结"全象限变体、平局走对角步进"的行为，用三个手工求得的像素序列钉死在测试里（含反向不对称性）。
- **无平局判据**：轴对齐与精确 45° 恒无平局；其余情形步进轴跨度为奇数 ⟹ 无平局（2·dy·Δx 与 dx·(2Δy+1) 奇偶性不同）。黄金场景全部选用无平局线。
- **性质测试兜底**：端点必画、绘制序 8-连通、每点到线段距离 ≤ 0.51 ——这三条不依赖任何参考实现，是算法正确性的独立证据。
- **端点定义**：直线连接两个整数格点（像素索引本身），而非像素中心；黄金图与性质测试均基于此约定。

## M3 — edge-function 三角形填充 + top-left rule

- **核心设计**：`rasterizeTriangle` 是 M3~M9 一切光栅化的唯一核心。屏幕空间逐像素直接求值三条边函数（不走向累积），换来与参考实现的逐位一致（IEEE 基本运算确定性），代价是每像素 ~10 次浮点乘加 —— 在 512² 场景下实测仍轻松 60fps，性能换确定性值得（M9 benchmark 有数据）。
- **top-left 规则推导**（y-down、正有向面积=视觉顺时针）：`E==0` 的采样点仅当边为 left（`dy<0`）或 top（`dy==0 && dx>0`）时包含。证明要点：相邻两三角形反向遍历共享边，方向 d 与 -d 中恰有一方满足该谓词 ⟹ 总和且互斥。
- **水密性验证不依赖参考实现**：600 对种子随机相邻三角形拼矩形，断言矩形内每个像素中心恰好覆盖一次、矩形外零覆盖 —— 这是不变量级的证据；1×1 到 40×40、两种对角线方向都覆盖。
- **解析覆盖计数**：直角三角形 (0,0)(8,0)(0,8) 的斜边恰穿过 i+j=7 的像素中心带，top-left 规则把这些点判给"另一侧"，故覆盖数 = #{i+j≤6} = 28，与实现输出一致。
- **环绕归一化**：area2 < 0 时交换 v1/v2（属性随之换序），调用方不需要关心顶点序；背面剔除是调用方基于同一 area2 公式的独立决策。

## M4 — z-buffer（屏幕空间线性 z 插值）

- **语义**：深度缓冲存视空间距离 d = -z_view（Float32，初始 +Infinity），测试 `d < depth`（严格小于）。黄金场景用**正交投影** —— 此时屏幕空间线性 z 是精确插值，参考/正式实现语义完全对齐，黄金图全里程碑保持回归有效。
- **踩坑**：`Framebuffer` 构造函数最初没把深度初始化为 +Infinity（只有 clear() 做），导致首版黄金图"双方都画了空图"假通过。教训：黄金对拍必须配一条**独立的内容性断言**（本里程碑补了遮挡/插值/平局三类）。
- **平局的真相**：`d < depth` 严格小于只在深度**逐位相同**时保证先画者赢。常数 z 的三角形插值结果是 (Σλᵢz)/Σλᵢ，浮点噪声可使其略小于 6.0 而被后画者覆盖 —— 这不是 bug，是 float64 插值的物理现实。二进制精确几何（2 的幂坐标 ⟹ 边函数/权重均为精确 dyadic 值）可构造逐位相同的平局，用它钉死先画者赢语义；非精确几何的同深度对只断言确定性（噪声方向冻结进黄金图）。真实 GPU 用定点深度正是为了消除这类噪声。
- **插值公式冻结**：d = (Σλᵢ·dOverWᵢ)/(Σλᵢ·invWᵢ)，一律直接除法。invW ≡ 1（仿射绘制）时退化为纯屏幕空间线性 z；M5 起透视绘制走同一条公式获得透视校正深度。

## M5 — 透视校正纹理（u/z、v/z、1/z）

- **核心公式**：屏幕空间线性插值 `(u/w, v/w, 1/w)`，逐像素 `u = (Σλᵢ·uᵢ/wᵢ)/(Σλᵢ·1/wᵢ)`。同一套机制顺手给出透视校正深度 `d = (Σλᵢ·dᵢ/wᵢ)/(Σλᵢ·1/wᵢ)` —— M4 的仿射路径（invW≡1）只是它的特例，一个核心吃下两种语义。
- **swimming 检验场**：黄金场景是掠射角地面四边形（近端 d=2、远端 d=8 的棋盘格），并配**解析对拍**：对 >2000 个深内部像素，用"像素中心光线与已知平面求交"独立算出 UV 再采样，要求与渲染输出逐位相同；同时断言屏幕空间线性 UV 在同一场景偏差 >0.02 —— 证明测试对"忘除 w"这类错误有杀伤力。
- **纹素边界歧义**：解析 UV 恰落在纹素边界 ±ULP 时，nearest 的格选择随浮点噪声翻转（如 u·64 = 48.0）。这不是插值 bug；解析对拍跳过边界 ±1e-3 的像素，黄金图不受影响（参考与正式同噪声同翻转，确定性保持）。
- **投影公式冻结**：`sx = (clip.x/w + 1)*0.5*W`、`sy = (1 - clip.y/w)*0.5*H`、一切属性 `attr/w` 直接除法 —— 参考实现逐位复刻同一串运算，IEEE 确定性保证对拍 0 容差可行。
- **采样器约定**：repeat 环绕（uu = u - floor(u)）；nearest = floor(uu·W) 钳位；bilinear = fx = uu·W - 0.5，索引环绕，先横后纵 lerp。

## M6 — 着色（Lambert + Blinn-Phong，Gouraud/Phong 两档）

- **光照公式**：`c = albedo⊙ambient + Σ[albedo⊙lightColor·max(N·L,0)·atten + lightColor·specular·max(N·H,0)^shininess·atten]`；方向光 + 点光（二次衰减 1/(1+k1·d+k2·d²)）+ 环境项。冻结约定：N·L ≤ 0 时该光源整体无贡献（含高光）——用轴对齐配置的手工锚定值（r=0.58 → 147.9 → 量化 148）钉死。
- **Gouraud vs Phong**：同一管线两种属性打包 —— Gouraud 逐顶点光照后插值颜色（attr=[r,g,b]），Phong 插值世界坐标与法线（attr=[P,N]，带纹理时 +uv 共 8 个）逐像素光照。插值后的法线不再是单位长度，逐像素重归一化。
- **踩坑（经典 y 翻转环绕坑）**：背面剔除最初写成"剔除 area2<0"，结果渲染出球体内壁（中心像素恰为纯环境光 22,8,7 暴露了它）。正确推导：视空间（y 上）CCW 的前向面，经投影 y 翻转后在 y-down 屏幕坐标里 area2 < 0 —— **前向面 = area2 < 0，应剔除 area2 > 0**。M5 的地面四边形因 doubleSided 掩盖了此错；教训：剔除逻辑必须有一个非 doubleSided 的3D黄金场景来验证（M6 球体正是）。
- **手工锚定 + 黄金对拍双保险**：轴对齐/半向量/衰减/背光四个手工用例锚定公式本身；球+立方体双模式黄金图锚定管线集成；另断言 Gouraud 与 Phong 黄金图必须不同（防止两档意外同路径）。

## M7 — 近平面 Sutherland–Hodgman 裁剪 + 屏幕 guard

- **裁剪空间与平面**：对 clip 空间半空间 `w >= ε`（ε=1e-6）做 S–H。透视投影下 w = -z_view，w=0 恰是过相机的平面；用 ε 而非 0 避免投影除法的数值悬崖，同时与片段深度丢弃阈值（d < ε）一致。正交投影下 w≡1，靠深度阈值兜底（本项目以透视为主）。
- **输出形状**：三角形对单平面 S–H → 顶点数 0/3/4 的凸多边形 → 扇形化 (o0, oi, oi+1) 恰为 0/1/2 个三角形，与任务表要求一致。单顶点在后 → 4 顶点（2 三角形）；双顶点在后 → 3 顶点（1 三角形）；单元测试逐一钉死。
- **冻结插值公式**：距离 dist = w - ε，交点 t = distA/(distA - distB)，全部分量（clip 位置、视距、varying）用同一 `out = a + (b-a)·t`。payload 在 clip 空间线性插值、投影时统一除 w —— 透视校正语义在裁剪后保持不变。顶点恰在平面上按内部处理（t=0/1 退化为复制顶点，产生零面积扇形瓣，由核心退化守卫自然跳过）。
- **快路径保回归**：全部在前时原样返回三顶点（不复制、不重算）——M1~M6 黄金图在管线重构后逐位不变（57 测试含全部历史黄金回归）。
- **屏幕边界 guard**：包围盒 clamp 到画布（ceil(min-0.5) / floor(max-0.5)）+ setPixel 双保险 + 非有限坐标防御；黄金场景中红三角四角出屏、绿/黄楔形近裁剪共同覆盖。

# 二期升级(软件光栅器 → 小型 3D 引擎,2026-11-15)

## P2-M1 — 场景图

- **TRS 结合序冻结是迁移等价的全部秘密**:局部矩阵 = `((T·Rz)·Ry)·Rx·S`,与一期 demo 的 `compose(T, Rz, Ry, Rx, S)` 从左到右逐对 mat4Mul 完全同序。恒等旋转 RotZ(0) 与恒等缩放经过 mat4Mul 逐位不变(IEEE:x·1=x;x+(±0) 不变号;-0 只在乘零时出现且加法吸收),单轴旋转的旧动画(T·RotY、T·RotY·RotX)因此逐位复现。锚定测试用 Object.is 逐元素比。
- **两种黄金图的分工**:锚点黄金图(升级前渲染一次性落盘,gen 脚本硬编码构造、永不重生成、不进 gen_all)防回归;独立参考黄金图(参考实现自己编码 TRS/层级/遍历,再喂同一 Renderer)防实现分歧。重新生成锚点会让前者退化为自我引用 —— 这是流程纪律不是代码问题。
- **items getter**:DemoScene.items 从稳定数组改为 getter(每次访问 updateWorldMatrices + collectDrawItems)。注意:animate 之后取 items 才含本帧 transform;collectDrawItems 本身不更新矩阵 —— 重建场景必须显式 updateWorldMatrices(round-trip 测试曾因此 11683 像素差异)。

## P2-M2 — 材质系统(多光源数组 + 聚光 + Lambert 开关 + mip 一档)

- **数组化光照的重构验证法**:LightSetup 从 {dir, point} 改为 {ambient, dirs[], points[], spots[]},累积顺序冻结 ambient→dirs→points→spots。单 dir+point 场景的浮点序列与旧版逐位同 —— 把锚点黄金图生成器改成数组形态重跑,`git diff golden/` 为空,重构等价性当场证明(比任何单元测试都硬)。
- **聚光的三处退化防御**:cosInner ≤ cosOuter → 硬锥(不产生除零 NaN);零轴 → 慢路径 continue、快路径预归一化写 NaN(cosΘ 恒 NaN 恒不命中 `> cosOuter`),两条路径语义对齐;恰在外锥(cosΘ == cosOuter)→ 无贡献(严格 >)。
- **mip 选层是启发式不是物理**:clip 空间 uv 二倍面积 × texW×texH / 屏幕二倍面积 ≥ 1 → mip1。uv 面积取裁剪期线性 payload,屏幕面积取投影后顶点 —— 定义冻结即可对拍,不追求透视正确的精确密度。逐子三角形选层(一个 4 顶点裁剪扇形的两瓣可以选不同层)。
- **powInt 沿用**:与 Math.pow 不逐位等价的老问题在新场景(新 light 数值/新 shininess)依然靠 8bit 量化吸收,黄金图仲裁 —— m6 的结论二期继续成立。

## P2-M3 — OBJ 与剔除

- **负索引的语义坑(本次最值钱的 bug)**:OBJ 规范"-1 = 最后定义的顶点"中"定义"指 **v 指令**。第一版实现用"当前输出数组长度"作相对基准 —— f 行的展开角点也在往同一数组追加,底面四边形展开 6 个角点后,侧面的 -1 指到了展开块末尾而非第 5 个 v 顶点。单测全绿(迷你用例无展开污染),独立参考实现对拍抓住(20 像素差异)。修法:原始 v/vt/vn 数据与展开输出分离,负索引只对原始列表解析;参考实现同步重写、黄金图重生成。
- **展开语义冻结**:输出 = 展开角点块(逐角点独立顶点,非索引复用),indices 直接指向该块 —— 渲染所需最小闭合网格,且 normals/uvs 与 positions 天然对齐(曾试过"原始块+展开块"拼接,raw 数量不一致时三数组错位,NaN 法线暴露)。
- **视锥剔除只做 5 平面**:本管线不裁远平面(远于 far 的几何仍被屏幕 guard 画出),按远平面剔除会改变像素 —— p2_frustum 黄金图里专门放了远平面外小球钉死"仍被绘制"。侧面/近平面外 ⇒ 投影全出屏 ⇒ 0 像素,剔除纯性能、像素安全。半径用 Frobenius 范数(σmax 保守上界)绝不误剔,边界 dist == -r 不剔。
- **遗留字段优先级**:Material.cullBackface 与 doubleSided 并存时,第一版让 doubleSided 抢先 —— 测试里两个都传,cull 开关失效。修正:显式新字段优先,旧字段仅作缺省回退。

## P2-M4 — 管线整合

- **排序默认关**:深度严格小于语义下顺序理论上不影响像素,但"逐位平局先画者赢"是冻结语义,demo 场景球-地切点恰是潜在平局。折中:opts.sortOpaque 显式开启(编辑器/游戏),配"开/关逐像素一致"测试;库默认保守。
- **正交相机**零难点(w≡1,近平面裁剪自然全过),mat4Ortho 一期就有,只差接线。

## P2-M5 — 编辑器

- **离屏画布默认 300×150 的坑**:putImageData(512²) 只落左上角裁剪,再被 drawImage 拉伸 —— 表现为"物体全部消失但拾取正常"(拾取走数据不走画布)。一行 off.width/height 修复。教训:初始化路径与 setScale 路径要共享同一套尺寸设置。
- **gizmo 拖拽的锚定**:移动增量 = 起止射线与相机面向平面交点差在轴上投影(28px → 恰 +1.09375 世界单位,精确有理数);旋转增量 = 环平面交点的 signedAngle(90° → 恰 π/2)。三环在轴交点处共用采样点,拾取测试必须选 45° 点避开歧义。
- **round-trip 的最终口径**:演示场景 → JSON.stringify → parse → 重建 → 渲染 == 升级前锚点黄金图,逐像素。JSON 数值往返精确(IEEE 最短表示可逆)是这条链成立的前提。

## P2-M6 — 演示游戏

- 逻辑全部纯函数化(node 可测):种子布局、相机相对移动、最短弧平滑转向(指数收敛,2s 后残差 ~1e-10)、严格 < 的圆形收集判定(FP 边界抖动:恰在 R 上的判定不可靠,测试改在 R·0.999 / R·1.001 处验证)、计分胜利重开。
- 纯逻辑动画:腿摆 ±0.55rad@2.6Hz 正弦、身体起伏、收集物悬浮自转 —— 全是 transform 插值,无骨骼(停止规则)。

## P2-M7 — 性能

- **顶点阶段无分配内联**:mat4ApplyPoint/Vec4/Dir 手动展开 + 矩阵元素提升局部变量。逐位等价论证:同一操作数、同一运算顺序、IEEE 确定性;证据:全部 21 张黄金图回归通过。1 万三角形场景 512²:18.0 → 16.25ms(62fps)。
- **像素填充是唯一主导成本**:全屏 phong+纹理地面单物体 8.9ms/帧。逐像素公式(直接除法、逐位平局语义)冻结不动 —— 62fps 已达标,更多要靠分辨率缩放(448² 78fps / 384² 98fps / 256² 172fps)。
- sWorld scratch 只写不读(一期遗留),删除。
